= Product model -- layout modes and session index
:navtitle: Product model

== Intent

Open Terminal is a **multi-mode** host. Decoupled index↔session windows and the DevCentr **project-grouped manager** are first-class layout modes, not the only ones. Users should also be able to **re-associate** sessions (or whole multi-tab UIs) with another process via a registration / thumbnail handshake.

== Layout modes (first-class)

|===
| Mode | What the user sees | Tab / surface relationship | Typical launch

| **Standalone**
| Classic Terminal-like UI: tabs along **top** or **left** (vertical tabs); tabs + live surface can share one OS window (WT-like).
| Tabs glued to (or co-located with) PTY chrome in one frame.
| Start Menu / app drawer — “I opened a terminal.”

| **Decoupled index**
| Calling/index window holds tabs and/or a thumbnail grid; live sessions live in **separate OS windows**.
| Tabs **not** glued to PTY chrome; index chrome and live surfaces are separate HWNDs.
| Controller / launcher / activity-style entry; multi-session desk.

| **Project-grouped manager**
| Dedicated manager window; tabs in **groups** = DevCentr projects that spawned them; **vertical tabs** ideal default.
| Manager chrome separate from DevCentr's project grid (grid stays in DevCentr). Live sessions follow association rules.
| DevCentr-spawned work; multi-project terminal desk.

| **Other** (future OK)
| Additional compositions (e.g. hybrid, embedded pane hosts).
| Do not over-specify in v0.
| TBD
|===

Users may switch modes or mix: e.g. a standalone multi-tab UI later re-associates under a decoupled index or project-grouped manager subscriber.

== Decoupled index (detail)

. Each terminal **session** may occupy a **real OS window** (session window).
. The **calling window** owns the **session index** -- presented as **tabs** and/or a **thumbnail preview grid**.
. **Tabs are decoupled** from the terminal surface. Classic WT keeps tab bar + PTY in one chrome frame. Here, index chrome (window A) and live PTY UI (windows B, C, ...) are separate.

----
+=========================================+
| CALLING WINDOW (index / chrome only)    |
|  [tab nu] [tab pwsh] [tab cmd]   ...    |
|  +-----+ +-----+ +-----+                |
|  |thumb| |thumb| |thumb|  preview grid  |
|  +-----+ +-----+ +-----+                |
+==================|======================+
                   | focus / spawn / close
     +-------------+--------------+
     v                            v
+------------------+    +------------------+
| SESSION WINDOW   |    | SESSION WINDOW   |
| PTY + vt cells   |    | PTY + vt cells   |
| dew chrome hooks |    | (own HWND)       |
+------------------+    +------------------+
----

== Project-grouped manager (DevCentr-spawned)

Dedicated **terminal manager** UI for sessions spawned from DevCentr.
**Vertical tabs** grouped by spawn-project are the ideal default.
Leave DevCentr's **project grid** in DevCentr -- do not move it into this manager.

----
+========+================================+
| Proj A |                                |
|  tab   |     focused session / focus    |
|  tab   |     pointer to session HWND    |
| Proj B |                                |
|  tab   |   last-CLI icon on tab chrome  |
+========+================================+

         highlight (default) / optional pipe
                    |
                    v
         [ DevCentr project grid ]
         active cell bright; others dulled
----

**Linking to the DevCentr grid:**

* **Default (B):** highlight the matching project cell/tab; dull siblings; user may swap focus via the grid.
* **Optional later (A):** visual "pipe" from manager window edge into the thumbnail/cell edge.

Architecture: link:https://github.com/openshellorg/shell-architecture/blob/main/docs/modules/ROOT/pages/devcentr-terminal-manager.adoc[devcentr-terminal-manager.adoc].
CLI icons on tab chrome: link:https://github.com/openshellorg/shell-architecture/blob/main/docs/modules/ROOT/pages/cli-app-icons.adoc[cli-app-icons.adoc].

== Session re-association / thumbnail handshake

Users re-associate **individual sessions** or a **whole multi-tab UI** with another process. The handshake sends **registration** info; the managing UI is typically a **subscriber**, not the sole owner of session processes.

=== Registration payload (sketch)

* Session / group id
* Tab array (order, ids)
* Titles (per tab / window)
* Thumbnail permission: whether thumbs are offered; **who generates** them
* Optional: shared-memory thumbnail address (or handle) for subscribers
* Layout mode hint of the source UI (standalone vs decoupled vs projectGroupedManager, etc.)
* Optional: `spawnSource` (`devcentr` | other), `lastCliAppId` for tab chrome icons

=== Thumbnail roles (ideal)

* **Session / host process creates** thumbnails (producer).
* **Managing / controller UI is a subscriber** (consumer of thumb frames / shm).
* Realtime thumbs should feel like the Windows taskbar live preview — note **performance**; prefer **shared-memory** thumbnail addresses over copying bitmaps per subscriber when possible.

=== Manager vs subscriber (v0)

|===
| Role | Meaning | v0 stance

| **Session process**
| Owns PTY + surface; visible in the OS taskbar as its own process/window.
| Always a separate process (taskbar-visible).

| **Subscriber**
| Controller / index UI that registers interest, shows tabs/thumbs, focuses/spawns/closes via association API.
| **v0 recommendation:** subscriber + separate session processes. Multiple subscribers allowed.

| **Manager** (later)
| Exclusive owner that may hide sessions from the taskbar and reject other subscribers.
| **Defer.** Differentiate only if product needs exclusive control; v0 does **not** require a sole manager.
|===

v0 ASCII (association model):

----
  [ Session proc A ]--produces thumbs--> shm / notify
  [ Session proc B ]--produces thumbs--> shm / notify
           ^                ^
           | register /     | subscribe (tabs, titles,
           | focus/close    | thumb permission, shm addr)
           |                |
     +-----+----------------+-----+
     |  Subscriber UI(s)          |
     |  index tabs / thumb grid   |
     |  (not exclusive owner)     |
     +----------------------------+
              ^
              | optional 2nd subscriber
     +--------+-------------------+
     |  Another subscriber UI     |
     +----------------------------+
----

Full protocol sketch: link:https://github.com/openshellorg/shell-architecture/blob/main/docs/modules/ROOT/pages/session-association.adoc[session-association.adoc] in `shell-architecture`. Stub types: `source/openterminal/association.d` (no IPC yet).

== Mapping to stack

|===
| Concern | Tech

| Session PTY
| `pty-d` (ConPTY / POSIX)

| Cell surface
| `vt-d` Emulator + Screen

| Session window paint
| `dew` + `vello-d` (monospace Consolas via `setUiFont`)

| Index / standalone chrome
| `dew` / `dui` (tabs, grid, thumbnails)

| Whole-UI DPI
| `dew.scale` / `App.contentScale`

| Open Shell top bar
| Host-chrome negotiation hooks (same capability catalog as WT fork)

| Env-refresh (near term)
| Remains on `openshellorg/terminal` until parity

| Association / thumbs IPC
| Spec first (`session-association`); implement later (shm thumbs TBD)

| Project-grouped manager chrome
| `dew` / `dui` vertical tab groups; DevCentr grid stays external

| CLI app icons
| Discover via `app.icon` / package assets (shell-architecture `cli-app-icons`)
|===

== Non-goals (this scaffold)

* Full WT feature parity
* Replacing the fork in one pass
* Full association IPC or production thumbnail pipeline (spec + stubs only)
* Exclusive manager role in v0
* Visual-pipe linking to DevCentr grid in v0 (highlight+dull first)
* Moving DevCentr project grid into Open Terminal

== Open questions

* Shared-memory thumbnail **perf** and lifetime (who maps/unmaps; refresh rate; multi-subscriber contention).
* When (if ever) to introduce an exclusive **manager** that hides taskbar windows / rejects extra subscribers.
* Handshake transport (local socket, named pipe, COM, dew bus) — undecided.
* Re-associating a whole multi-tab standalone UI as one registration group vs per-session only.
* Thumbnail **permission** UX: opt-in per subscriber vs session-global offer.
